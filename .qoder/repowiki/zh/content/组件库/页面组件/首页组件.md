## 项目结构
前端采用 Vue 3 + TypeScript + Pinia + Tailwind 的典型 SPA 结构。首页位于 views 层，通过路由进入；数据通过 api 层请求后端；状态由 stores 层集中管理；类型定义在 types 中统一维护。

首页的数据流遵循"视图 -> API -> 状态 -> 视图"的单向数据流模式，结合 Pinia 进行跨组件状态共享。

A-->>V : "返回结果"
V->>S : "写入列表/分页/错误等状态"
V-->>U : "渲染文档列表、分页控件与轮播图"

## 性能考虑
- 请求优化：
  - 防抖搜索，降低重复请求
  - 分页加载，减少首屏体积
  - 合理缓存：对相同查询结果做短期缓存
- 渲染优化：
  - 虚拟滚动（大数据集场景）
  - **图片懒加载**：轮播图中的图片按需加载，减少初始加载时间
  - 图片占位符：加载过程中显示占位图提升感知性能
- 资源优化：
  - 按需引入第三方库
  - 压缩静态资源与启用 CDN
  - **内存管理**：及时清理轮播图的定时器，防止内存泄漏
- **轮播图性能**：
  - 预加载相邻图片，提升切换流畅度
  - 节流动画频率，避免过度重绘
  - 移动端优化触摸事件响应

**更新** 新增了轮播图相关的性能优化策略，包括图片懒加载、内存管理和移动端优化

## 故障排查指南
- 搜索无结果：
  - 检查搜索词是否为空或过短
  - 确认后端是否支持对应过滤字段
  - 查看网络面板请求参数是否正确
- 分页异常：
  - 校验 page、size 合法性
  - 检查后端返回的分页元信息是否完整
- 网络错误：
  - 检查 client 的错误拦截与重试策略
  - 查看 CORS、鉴权头是否正确
- 权限问题：
  - 确认 auth store 中的登录态是否有效
  - 必要时引导重新登录
- **轮播图问题**：
  - 图片加载失败：检查图片URL有效性，查看控制台错误信息
  - 自动播放异常：验证定时器是否正确创建和清理
  - 触摸事件失效：检查移动端兼容性，验证事件绑定

**更新** 新增了轮播图相关的故障排查方法
