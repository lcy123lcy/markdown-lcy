应用以 `src/main.ts` 为入口，依次挂载 Pinia、Vue Router 4 和 Element Plus（含全部图标），根组件 `App.vue` 通过 `<router-view>` 渲染页面并组合 `DocumentSidebar` 侧边栏。
- 路由层 (`router/index.ts`)：使用 `createWebHistory`，按 `meta.requiresAuth` / `meta.guest` 声明式标注路由权限，由 `router.beforeEach` 集中拦截跳转。
- 状态层 (`stores/`)：Pinia store 采用 Composition API 风格；`auth.ts` 管理用户令牌与用户信息并通过 `localStorage` 持久化到 `auth` 键；`editor.ts` 维护当前 Markdown 内容与配置；`index.ts` 暴露 `useAppStore` 管理主题等全局状态。
- API 层 (`api/`)：`client.ts` 封装带 Bearer Token 的 `fetch`，在 401 时调用 `authStore.refresh()` 重试一次，失败则清空认证并重定向首页；`auth.ts`、`documents.ts` 分别实现认证与文档 CRUD。
- 视图层 (`views/`)：`Login.vue`、`Register.vue`、`Home.vue`、`DocumentEdit.vue`、`NotFound.vue` 对应路由；`DocumentEdit.vue` 承载富文本编辑流程。
- 组件层 (`components/`)：`MarkdownEditor.vue` 是核心 WYSIWYG 编辑器，通过 `contenteditable` 配合 Turndown（HTML→Markdown）、highlight.js（代码高亮）与自定义目录逻辑工作；`Toolbar.vue`、`DocumentSidebar.vue` 作为子组件被复用。
- 工具层 (`utils/`)：按职责拆分 `markdown.ts`、`image.ts`、`toc.ts`、`export.ts`、`stats.ts`、`editor.ts`，被组件按需引入。
依赖方向自上而下：views → components → stores/api/utils，API 仅依赖 stores 中的 auth 状态，不反向依赖 UI。
